# 逐章逐卷记忆与唯一正史

## 权威顺序

作者明确锁定的设定与已接纳正文有冲突时先报告并按修订治理解决，不能偷偷选一份覆盖另一份。未来细纲、推演、审查意见不是已发生事实。

使用现有oh-story追踪的书：`追踪/_tracking-state.json`是唯一结构化权威；上下文、角色状态、伏笔、双时间线、长期事实与关系清单由原 `tracking_commit.py`生成。新技能不增未知schema字段、不手改这些视图。

辅助世界包记录决策与引用，不成为第二world-state。导出放 `创作运行/派生视图/`，带来源和可重建标识。静态角色/势力设定仍在批准的 `设定/`卡中。

## 接入新书与旧书

- 新书：先建角色、势力与大纲，在获授权的项目初始化中用原追踪协议从单元0初始化；不能用新门工具偷偷建权威。
- 已有正文且已有权威：先 `tracking_commit.py check`。追踪章号、正文和接纳闭环冲突时先定点修复，不把正文存在自动视为追踪完成。
- 旧书没有权威：导入已有已接纳范围，保留证据不足；不能伪造逐章日更事务，亦不能从旧审查报告当正文重建真相。
- 当前状态/派生卡损坏：按原协议重跑相关事务修复。世界投影坏了只重建投影，不编辑追踪Markdown。

## 最小恢复顺序

1. 原追踪 `check`取得当前章、修订号；对照接纳/闭环状态。
2. 读 `追踪/上下文.md`：故事时间、地点、未完动作、下一单元承诺。
3. 读本章细纲、卷目标和上一已接纳单元；当前章作者计划不覆盖上一章发生过的事。
4. 定点读行动者静态卡和当前快照；角色久别时召回个人事件、获得信息与资源变化。
5. 检索涉及事实/关系/能力权限，区分作者、读者和角色认知。
6. 检查活跃伏笔、到期承诺、时间经过与幕后触发。
7. 生成只包含本场必需材料的上下文包，注明来源版本。

缺关键来源先查；不存在就写未知/待核。不要整卷全文塞进每章prompt，也不要只凭上一章摘要决定老角色状态。

## 每章正式入账：内容与接口

记录实际发生，不记录为了过七关而拟定的事情。至少核对：

| 变化 | 原追踪接口 |
|---|---|
| 本章结果与未来相关后果 | `delta.result`、`character_changes`、`constraints`、`next_chapter_commitments` |
| 位置、目标、伤病、关系、能力资源、知识、未结事项 | 允许字段的 `character_snapshots`；连续性变化用 `continuity_changes` |
| 知情获得、个人行为、幕后实际行动与故事时间 | 独立 `timeline_events`，`characters`指参与者；客观事实与读者所知分开 |
| 身份、关系、物权、权限、能力规则、不可逆事实 | `fact_changes`，稳定K/R ID、正文/锁定设定证据与禁止误读 |
| 埋/推进/回收/放弃伏笔 | `foreshadow_changes`的原生允许状态，不自行新增schema枚举 |

“深化/部分兑现”在当前summary、章节变化和原始证据中说明，未完整兑现仍保持已埋；“到计划回收章”不等于已回收。伏笔的一个局部承诺兑现不自动解决整条长线。

信息变化要写“本人亲见/听某人转述/推断/误信X，来源E编号与时间”，不是只写“知道秘密”。重要信息获得单独E事件，别一条E不断覆盖十年人生。

现有schema严格限制字段与容量：上下文12KB，逐章记录硬上限3KB，单核心快照8KB。七关、完整声线和检查日志不能塞进去。全书人物库不限于当前上下文最多六人。

所有正史写入由一个主写者串行提交，版本号不是并发锁。子代理可以并行提建议或只读审查，不并行写同一本书的权威状态。

## 候选记忆与接纳闭环

写前包、写后包、拟事件增量、新角色提案全部留在候选/规划工作区，标候选。写后审核依据实际正文，不能直接将细纲计划转成事务。

长篇：候选通过→用户接受或本次有效auto授权→原工具approve/promote→唯一追踪事务commit/check→原候选close→世界视图重建。任一步失败保留现场，不继续下一章；不手改视图“修绿”。

新角色正式静态卡只在接纳后归档。若修改已有已接纳事实，走revision治理并标受影响后续；不在候选门里顺便回改全卷。

短篇：见integration单独适配，不使用长篇正文路径或伪造章节提交清单。一次性片段尚未接纳时只保留工作记忆，不宣称世界状态已推进。

## 逐章/逐卷视图

每个接受单元都必须有原追踪的紧凑变化记录；世界工具按相应范围导出人物时间线、逐章证据和卷回看。每章收尾可用本卷起章到当前章生成累积回看；卷末对整卷范围最终核对。

默认 `创作运行/派生视图/`是可更新的当前阅读视图。每卷结束另用 `--output "创作运行/卷末记录/第N卷_A-B_r修订号"`导出并保留本卷版本；下卷不能覆盖上一卷记录。卷末的人格/声线/因果与继承检查放同一卷独立的人工复核文件，不写进可重建生成页。未闭卷范围标“截至第B章回看”，不得冒称整卷审结。

卷回看至少检查：

1. 实际事件与时序，哪些只是尝试、猜测或未来计划。
2. 每个长期角色的目标、得失、位置/资源、信念和关系变化。
3. 幕后计划的成功、失败、等待、取消及未展现后果。
4. 伏笔本卷首埋、深化、部分兑现、完整回收、放弃与未结项。
5. 已履行/违背/延期的承诺；代价由谁承担。
6. 下卷必须继承的硬事实、人物知识、未完动作与到期项目。
7. 源文件哈希、权威修订号、接纳正文范围、证据不足与再建方法。

当前state会upsert；**不能只用当前伏笔状态倒推每章曾经的状态**。历史回看须引用逐章记录、实际已接纳正文及合法历史材料。工具没有完整旧材料时写“待核”，作者定点读原文核对；不得填“已回收”取悦验收。

人工补充分析放非权威卷工作包并逐项引用；再导出可被重建替换，不往生成文件直接加新事实。确实漏了正史事件，先用有证据的同章revision事务维护权威，再重建。

## 修订、过期与反遗忘

正文、角色卡、细纲、状态修订号变更会使原行动包失效；稿件改一字，写后哈希也应更新并重验。不能给旧PASS换文件名继续用。

修改历史章后，沿事件/角色/关系/伏笔引用找直接受影响后续，再核对该范围；不默认全书重写。未受影响资料可继续使用，过期投影重建。

每次新会话/compact都重新走恢复顺序。这是把忘事变成缺项、旧版本或来源不符的可检测问题，不是承诺模型凭记忆永不遗忘。
