# 小说自主世界引擎

目标：人物先有自己的生活、利益、认知和选择，故事从他们相互影响中发生。主角是观察入口之一，世界不因他缺席而停摆。长期连续性依靠落盘证据、恢复检查与章卷闭环，不依赖聊天记忆。

## 0. 安装位置与生效方式

- **唯一正本**：`skills/story-world-engine/`（SKILL.md + `references/` + `assets/` + `scripts/`）。项目内其他运行时目录（`.opencode/skills/`、`.claude/skills/`、`.codex/skills/`、`.agents/skills/`）是同一份内容的镜像；改动正本后在仓库根运行 `skills/sync-story-world-engine.ps1` 同步，冲突一律以正本为准。
- **正本优先**：项目本地 `skills/story-world-engine/` 存在时优先使用；否则使用当前已加载的本技能目录。脚本路径相对所选技能目录，不硬编码用户主目录。
- **生效方式**：有 hooks 的运行时由 hooks 强制接入；Codex 由 `allow_implicit_invocation` 与宿主决定；Web AI / 通用端只靠 `AGENTS.md` 与写作入口路由，写作者必须自行遵守（见 §6）。
- **环境**：脚本仅需 Python 3.10+ 标准库；先探测 `python3`/`python`/`py`。脚本或 `references/` 缺失时按 §7 降级，不静默空转。

## 1. 自动接入与优先级

- 所有涉及小说新行动、新台词、新事件或修改它们的任务，先执行本技能，再与 `story-long-write` / `story-short-write` 或当前写作流程协同。开书/大纲用 planning；已有小说续写用 continuation；重写只重评受影响行动及后续依赖。
- 每位作出选择、说出会影响局势的台词或会复现的人物都要有独立卡和时间线引用。主角、配角、反派、普通人、未具名但改变局势者一视同仁。
- 功能位、情绪公式、爽点和卷纲可以决定镜头选择，**不能决定角色违反自己知识、欲望、能力和代价去配合剧情**。旧手册“无条件维护主角”“配角抢风头就换人”遇到冲突时不执行。
- 不授权额外章数、自动定稿、改变锁定事实或平台发布。已有候选/接纳/修订/语言门继续执行。
- 本技能不直接改写正文、不直接写追踪正史；追踪只经原追踪工具提交。

## 2. 七关：每项有根据，答不上原因才阻断

动手包括：协助、拒绝、撒谎、泄密、隐瞒、索价、承诺、离开、使用能力，以及有后果的选择不行动。连续机械小动作可引用同一决策许可；新信息、目标、风险、时间或能力条件改变时必须重评。

| 关 | 要答清楚 | packet 字段 | 常见伪回答 |
|---|---|---|---|
| 1 知道什么 | 从何处、何时取得；亲见/转述/推断/误信/未知分别是什么？作者知道不等于他知道。 | `knows` | “他很聪明所以知道”“作者已写过” |
| 2 想要什么 | 本人此刻要争取什么，与长期生活目标怎样连接，冲突时先保什么？ | `wants` | “帮助主角找到线索” |
| 3 怕失去什么 | 地位、钱、关系、自由、体面、安全或自我认知，具体是哪一个？ | `fears` | “怕主角失败”“什么都不怕” |
| 4 能不能做 | 技能、资源、权限、位置、时间、伤病与可信渠道是否允许尝试？会做不等于必成功。 | `capability` | “认识组织所以能调全部档案” |
| 5 没有剧情需要还会选吗 | 撤去作者预定结局，这个选择在他所知和利益下是否仍成立？至少比较一个合理备选。 | `no_plot` | “必须这样才能进入下一章” |
| 6 代价与约束 | 他愿付什么、拒付什么，有哪些不可跨越或可冒险的现实限制？ | `costs` | “愿付出一切”“代价以后再说” |
| 7 后果与世界回声 | 预期收益/失败/误解会影响谁，谁会独立回应，哪些承诺或长期后果应入账？ | `consequences` | “这证明他成长”“反派因此必败” |

- **阻断条件只有一条：作者答不上原因**。角色不知道、判断错、贪婪、嫉妒、逃避或失败都可以通过；合理未知/待核可以作为“边界明确的不知道”通过（写清只知什么、不知什么），不能整项 `unknown` 却标 passed。常见伪回答与最小修复见 `references/seven-gates.md §2`。
- 先召回证据、补合理准备或改选另一行动，不能以“剧情需要”“他忽然想通”“方便主角”填写。阻断受影响行动，不冻结其他独立且已通过的工作。
- 七关表不进入正文旁白或台词；脚本只检查缺项、引用、顺序、覆盖和指纹，不能自动证明人物心理真实，必须有人工语义审查。

## 3. 人物、势力与世界卡

- 建卡门槛：跨 2 章以上出场、改变主线局势、或会被复现声线的人物建独立卡；纯布景用 `coverage.background_only:[{name,reason}]` 登记，不伪造几十张卡。
- 每卡至少有稳定身份/别名、独立生活目标、欲望排序、怕失去、能力及渠道上限、缺陷诱因和代价、关系差异、信息取得来源、声线和证据。长期角色扩展，临时人物可紧凑，但不能没有选择来源。
- 缺陷可以是贪婪、嫉妒、控制欲，也可以是讨好、怕丢脸、过度负责、固执或双标。缺陷必须影响选择，不强制每人有恶行。
- 声线记录表达策略、称呼、句式、隐瞒方式、压力变化和真实台词锚点；不让所有人用同一审核语言，不机械给每人发口头禅。
- 人物时间线引用已接纳事件、取得信息、资源/位置变化、关系和未履约承诺；它是来源绑定的阅读视图，不是第二正史。
- 势力有执行者、情报源、利益、资源、权限、内部冲突和失败条件；见 `references/world-clock.md` 与 `assets/faction-card.md`。

## 4. 每章/每节执行顺序

1. **恢复**：读 `{书名}/追踪/上下文.md`、上一已接纳单元、本章细纲/卷目标；定点读行动者卡、个人事件、涉及事实和活跃伏笔。先用原追踪工具校验 `_tracking-state.json` 与派生视图同步，不同步先重建。缺失或冲突不靠记忆补造，标待核。
2. **世界时间**：确认故事经过多久、哪些独立计划触发；把变化写入 `{书名}/追踪/时间线` 与势力议程（`references/world-clock.md` 模板）。允许等待、失败、取消或没有新大事。幕后候选计划不能提前成为既成事实。
3. **决策**：列出全部场景和行动者，逐项七关；通过后冻结写前包（路径见 §5）。人物合理拒绝时调整路线，不把他强行改成配合者。
4. **候选生成**：只向正文作者传必要人物状态、差异声线、可知信息和具体行动约束。七关答案不进正文。
5. **写后复核**：以实际正文对照覆盖、因果、知识、能力、声线、代价与后果；先过原写作语言门；按 `references/seven-gates.md §6` 七问复读。角色合理误判须在正文显式呈现依据，不能与作者写错混判。意外新增的重要动作必须先补七关并重验。
6. **记忆闭环**：从实际文本提取事件、人物变化、埋/推进/部分兑现/回收/放弃伏笔，用原追踪工具 `tracking_commit.py` 串行提交；复检后重建派生视图。
7. **卷末/篇末**：核对实际事件、得失、人物变化、计划成败、伏笔账、未履约承诺和下卷继承。历史资料不足标待核，不能由当前状态反推当年全部事实。

新书/一次性场景可以用 planning 先设计卡与大纲；已有正式历史的续写不得以 planning 绕过恢复。短篇以小节为追踪单元、全篇为卷级回看；七关可按关键选择合并为轻量包，见 `references/integration.md`。

## 5. 可运行的检查与派生（world_gate.py）

Python 3.10+ 标准库；机器字段以 `references/packet-contract.md` 为准。`{SKILL}` 为技能正本目录，`{书根}` 为单本书目录，`{原工具}` 为原追踪工具 `tracking_commit.py` 的路径。

```bash
# 先探测解释器：python3 / python / py 任一可用即可
python "{SKILL}/scripts/world_gate.py" init --project "{书根}" --chapter N --mode continuation \
  --tracking-tool "{原工具}" --source "大纲/细纲_第N章.md" --source "设定/角色/某人.md" \
  --packet "追踪/候选章/第N章/{run-id}/世界引擎/写前行动审查.json"
python "{SKILL}/scripts/world_gate.py" check --project "{书根}" --packet "{写前包}" --phase prewrite --tracking-tool "{原工具}"
python "{SKILL}/scripts/world_gate.py" check --project "{书根}" --packet "{写后包}" --phase postwrite --tracking-tool "{原工具}"
python "{SKILL}/scripts/world_gate.py" export --project "{书根}" --start 1 --end 99 --tracking-tool "{原工具}"
```

- `init` 产生未填、未审模板（`TEMPLATE_CREATED_UNREVIEWED`），**不是 PASS**。写后包复制冻结前包，另填实际正文、结果和复核，不修改已绑定的前包。
- 写前包、写后包必须放在候选 run 目录内（`追踪/候选章/第N章/{run-id}/世界引擎/`），否则写后包无法递归复验、候选接纳门对不上。
- `init`/`check`/`export` 必须传同一个 `--tracking-tool`；不能换校验器更换冻结基线。退出 0 = `STRUCTURAL_CHECK_PASS` / `TEMPLATE_CREATED_UNREVIEWED` / `DERIVED_VIEWS_EXPORTED`；退出 2 = `FAIL`，`errors` 给原因。
- `world_gate.py` 只做检查/导出，不写正文、不写追踪、不接纳正史；追踪提交只走 `tracking_commit.py`。

## 6. 自动与硬门边界

| 平台 | 实际行为 |
|---|---|
| 有 hooks 的运行时（Claude Code / OpenCode 插件等） | hooks 硬拦截，未过门不能写下一章 |
| Codex（`allow_implicit_invocation: true`） | 宿主按相关度自动调用；不保证每次触发，写作者仍需自查 |
| Web AI / 通用端（无 hooks） | 不会自动执行；靠 `AGENTS.md` 与写作入口路由，写作者手动遵守 |

- 启用 `设定/世界运行契约.json`（`enabled: true`）后，已集成的长篇 `chapter_candidate.py` 会在检查、批准、晋升前调用两阶段门；缺包、换稿套包、来源过期或未通过均阻断该候选。启用字段与位置由项目负责人维护。
- 短篇不冒用长篇接纳工具，按 `references/integration.md` 适配。
- 技能发现遵循平台刷新/新会话机制；项目已有 `AGENTS.md` 文件路由。

## 7. 环境自检与降级

1. 探测解释器：`python3` / `python` / `py` 依次尝试；都没有则降级人工流程。
2. `references/`、`assets/`、`scripts/` 缺失或不可读时，报告缺失文件并降级人工七关，不静默空转。
3. 原追踪工具不可用、`_tracking-state.json` 损坏时，停止导出与提交，报告并请求修复，不另建世界状态。
4. 降级声明格式：`Fallback: story-world-engine tool unavailable -> manual`（或对应原因）。

## 8. 收尾交付

- 正常写作汇报只给候选/定稿状态、关键变化、门结果及文件链接，不向读者展示审查流水。
- 有阻断时报告：**哪项行动、哪一关、缺什么来源/条件、怎样最小修复**；不可写下一章绕过欠账，不自行扩大修订历史范围。
