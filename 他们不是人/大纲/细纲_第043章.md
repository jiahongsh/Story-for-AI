# 细纲 · 第43章 紧急联系人

## 第 43 章：紧急联系人
- **核心事件**：许棠因为被标成“长期访客/非家庭成员”，不仅门禁权限受限，物业紧急联系人也被系统自动清空。当天许德昌在楼下短暂眩晕跌倒，物业工作人员按新系统查询时找不到家庭联系人，只能先联系120和社区值班。真正把许棠叫回来的，是305大姐用自己手机打给她。许棠赶到后发现，昨天她的手机号还在旧物业纸质登记册“女儿/紧急联系人”一栏里。镜辞借此拿到一份非常清楚的前后版本对照：关系事实没有消失，但系统已经开始让这段关系失去实际权限。
- **字数目标**：3000 字
- **阶段位置**：第一卷阶段2；第43章；安平里关系单元现实后果
- **单元ID/位置**：1-4；第3拍·关系分类产生行动后果
- **目标情绪**：普通上午 → 突发跌倒 → 查不到联系人 → 许棠赶回 → 旧纸册与新系统冲突 → 风险从称呼进入现实
- **主角目标/关键选择**：镜辞想知道标签变化是否只停在嘴上；关键选择=在突发事件里不把调查优先于救人，先协助联系许棠/急救，再保存版本证据
- **章节定位**：现实后果章；让抽象身份分类第一次造成可见代价
- **本章结构公式**：节点1（许德昌楼下跌倒） + 节点2（物业新系统无家庭联系人） + 节点3（邻居私人电话联系许棠） + 节点4（老人无大碍） + 节点5（旧纸质登记册发现许棠原本是紧急联系人） + 节点6（新旧版本并存）
- **章首钩子**：许德昌倒在楼下时，物业电脑里“家庭紧急联系人”那一栏是空的。可305大姐第一反应却是：“快给棠棠打电话。”
- **本章即时兑现**：第42章“关系解释变化”升级成具体权限变化；系统开始影响谁能被现实机构承认为家属/联系人
- **本章禁止提前释放**：系统为何自动清空、幕后技术名称、群体记忆同步、唯一指向
- **能力边界**：本章解决的是制度/数据后果，不需要镜返出手；镜辞看不到接缝也不能据此判断“这是纯普通软件Bug”
- **契约风险**：契约安全。突发事件首先按现实急救处理，不拿老人身体当悬疑机关拖延救助

#### 内容概括（五段式）
- **起因**：上午许德昌下楼买菜，在单元门口突然眩晕，扶墙没扶稳，坐倒在地。镜辞正好在附近观察施工后状态，先帮忙把人挪到安全位置、让物业打120。老人意识清醒，只说头晕。
- **发展**：物业工作人员打开新住户系统找家属。302室许德昌名下只显示本人，没有“家庭成员”紧急联系人；许棠因为前一天被归到“长期访客”，号码不在默认联系列表里。工作人员只能按流程联系社区值班和急救。
- **转折**：305大姐根本没查系统，直接掏自己手机给许棠打电话：“你爸摔了，快回来。”十几分钟后许棠赶到。老人检查后问题不大，主要是低血糖和起身过快，现场紧张才缓下来。
- **高潮**：许棠问物业：“我昨天不是留了手机号吗？” 老物业人员翻出柜子里尚未销毁的纸质登记册。旧册302页写得很清楚：`许棠——女儿——紧急联系人`，连续几年都没改。新系统上线后，这一栏不是被人手动删除，而是因为她的“关系类型不符合家庭成员”而没有被迁移。
- **结尾**：镜辞得到许德昌和许棠允许后，只拍了旧登记册相关一页与新系统当前页面，不带无关住户信息。他把两张照片并排：昨天以前，系统可以承认她是紧急联系人；今天，它说她只是访客。人没变，手机号没变，共同生活没变。变的是系统允许这段关系做什么。

#### 情节安排（多线）
- **主线推进**：安平里关系分类开始改变实际权限，而非只改变称呼
- **辅线推进**：纸质旧版本成为重要对照，呼应猫眼“旧版本不能丢”方法
- **事件线/任务线**：跌倒 → 急救 → 系统查无联系人 → 邻居私人联系 → 旧纸册 → 新旧对照
- **任务卡点**：镜辞想观察关系变化 → 突发事件打断调查 → 先救人 → 事件反而自然暴露系统权限问题
- **感情线/关系线**：305大姐虽然口头上受新标签影响，却在真实危机里仍第一时间联系许棠，显示关系并没有被一句系统标签彻底抹掉
- **逻辑线**：许棠从家庭成员降为访客 → 紧急联系人迁移失败 → 现实救助流程失去最熟悉的人 → 旧册证明这是新系统造成的状态变化

#### 人物关系和出场顺序
- **出场顺序**：许德昌 → 镜辞/物业人员 → 305大姐 → 许棠 → 急救人员
- **人物关系变化**：305大姐的“嘴上重新分类”和“行动仍找棠棠”出现差异，为下一章验证关系后果提供关键材料
- **视角/信息差**：读者与镜辞知道旧纸册存在，仍不知道是谁设计了迁移规则、是否故意针对这类非标准关系
